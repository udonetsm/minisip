# MiniSIP

!ВНИМАНИЕ! Это приложение полностью сгенерировано нейросетью. Будте внимательны с тем что передаете через него. Приложение не проходило аудит безопасности и полноценное нагрузочное тестирование.

Минималистичный, производительный SIP-клиент и IKEv2/ESP VPN-клиент для Android.
Приложение написано полностью без сторонних библиотек: протоколы **SIP, SDP, Digest, RTP, G.711, IKEv2 и ESP** реализованы с нуля.

Нужны только стандартная платформа Android SDK 35 и Java 17.

---

## 🏗 Архитектура

Проект строго разделен на изолированные пакеты. Каждый пакет предоставляет один публичный интерфейс и статическую фабрику `create(...)`. Реализации скрыты внутри пакета (`package-private`).

```
ru.minisip
├── net     Udp      ← Чистые сетевые сокеты и привязка к сетям (Android ConnectivityManager)
├── media   Media    ← RTP, G.711 кодек, микрофон и динамик (AndroidAudio, AudioRecord, AudioTrack)
├── sip     Sip      ← Протокол SIP (REGISTER, INVITE, BYE, CANCEL, Digest-MD5, SDP)
├── screen  Screen   ← Управление экраном и датчиком приближения
├── vpn     Vpn      ← IKEv2/ESP VPN-клиент, tun-интерфейс, обработка пакетов
└── app              ← Корень композиции, логика сессий и UI на Material 3
```

### Принципы архитектуры:
- **Отсутствие зацепления**: пакеты не зависят друг от друга напрямую, а общаются только через интерфейсы.
- **Встроенные типы на границах**: между пакетами ходят только базовые типы Java (`String`, `int`, `byte[]`, `boolean`) и интерфейсы-слушатели.
- **Проверка импортов**: скрипт `python3 tools/check_imports.py` автоматически валидирует правила слоев.

## 📱 Функциональность и возможности

### 1. Подключение к АТС (SIP)
- Регистрация на SIP-сервере с поддержкой авторизации **Digest-MD5**.
- Поддержка отправки `Expires: 0` при отключении для мгновенного снятия регистрации на сервере.
- Автоматическая защита от звонков при отсутствии активного подключения: если связи с АТС нет, звонок не запускается и фоновые процессы не расходуют ресурсы.

### 2. Исходящие вызовы и Звуковой тракт
- **Только исходящая связь**: входящие звонки отсекаются с авто-ответом `486 Busy Here`.
- **Захват аудиоустройств**: использование `AudioRecord` (`VOICE_COMMUNICATION`) и `AudioTrack` с системным эхоподавлением и подавлением шумов.
- **Устойчивый старт аудио**: циклический прогрев звукового драйвера (до 5 попыток с интервалом 100 мс) гарантирует успешную инициализацию микрофона/динамика с первой попытки даже при пробуждении смартфона из глубокого сна.
- **Управление звуковым фокусом (Audio Focus)**: при старте звонка запрашивается эксклюзивный фокус `AUDIOFOCUS_GAIN_TRANSIENT_EXCLUSIVE`. Любое стороннее медиа (музыка, видео, плееры) автоматически ставится на паузу. По завершении вызова фокус сразу освобождается.
- **Поддержка Early Media**: обработка ответа `183 Session Progress` / `180 Ringing` с SDP для проигрывания гудков или голосовых сообщений прямо от АТС, с бесшовным переходом на разговор при ответе (`200 OK`).
- **Переключение вывода**: переключение на лету между разговорным динамиком (earpiece) и громкой связью (speakerphone).

### 3. IKEv2/ESP VPN-клиент
- **Режимы авторизации**:
  - Вход по логину и паролю (EAP-MSCHAPv2, подходят сервера strongSwan, Windows RRAS и др.) с валидацией цепочек X.509 сертификатов (системное хранилище или пользовательский PEM CA).
  - Вход по общему ключу (PSK).
- **Раздельное маркерное шифрование (Split Tunneling)**: выбор конкретных приложений через системный диалог, чей трафик должен направляться в туннель (`VPN apps`).
- **Привязка сокетов**: после подъема туннеля SIP- и RTP-сокеты привязываются строго к интерфейсу `tun0` через `Network.bindSocket`.
- **Умный Healthcheck и экспоненциальный реконнект**:
  - Отправка сырых ICMP Echo-запросов через ESP каждые 2 секунды.
  - Потеря фиксируется только при **3 подряд необработанных ответах** (6 секунд).
  - При потере связи звонок не сбрасывается сразу: VPN входит в режим переподключения (`recover()`) до ~2 минут. При успешном восстановлении звонок продолжается без разрыва.
  - Счетчик попыток выводится в статус: `VPN: reconnecting (попытка N)` / `>99`.
- **Корректная обработка вытеснения (Takeover)**: при запуске другого VPN-клиента в системе MiniSIP мгновенно завершает вызов, закрывает сокеты и отключает АТС без ухода в бесконечный цикл переподключения.

### 4. Датчик приближения (`Screen`)
- Экран гаснет при поднесении телефона к уху (`PROXIMITY_SCREEN_OFF_WAKE_LOCK`) и включается при отстранении.
- После завершения разговора экран остаётся погашенным до отстранения смартфона от лица.

### 5. Пользовательский интерфейс (Material 3)
- Построек полностью на интерфейсных компонентах **Material 3** без использования XML-ресурсов разметки.
- Поддержка нескольких страниц настроек (многоаккаунтность) через `ViewPager2`.
- Разделение элементов на три визуальные карточки с закругленными углами (`16 dp`):
  1. **Настройка АТС сервера** (Сервер, Login, Password, Connect / Disconnect, статус).
  2. **Вызов и источник звука** (Number, Call / Discard, выбор источника вывода).
  3. **Настройка VPN (IKEv2)** (VPN Server, Login, Password, спойлер «Дополнительные настройки», выбор приложений, Connect / Disconnect, статус).
- **Спойлер дополнительных настроек**: скрывает второстепенные поля (PSK ключ, CA сертификат и `Healthcheck address`).
- **Фоновый DNS-резолвинг**: в поле `Healthcheck address` можно указывать как IP-адрес, так и доменное имя. Если указан домен, приложение разрешает его в IPv4 в фоновом потоке перед стартом туннеля (с откатом и понятным сообщением об ошибке при сбое).

## ⚙️ Сборка проекта

1. Откройте проект в **Android Studio** (AGP 8.7.3+, Gradle 8.9+).
2. Или соберите из консоли при наличии Android SDK 35:
   ```bash
   ./gradlew assembleDebug
   ```

## 🧪 Тестирование без Android SDK

В папке `jvmtest/` подготовлены автономные JVM-тесты, не требующие запущенного эмулятора или Android SDK:

```bash
sh jvmtest/run.sh
```

### Проверяется автоматически:
- Архитектура импортов между пакетами (`check_imports.py`).
- Кодек G.711 и парсинг RTP.
- Авторизация SIP Digest-MD5 по RFC 2617.
- Привязка сокетов к сетевым интерфейсам (`NetTest`).
- Криптография и ESP: HMAC (RFC 4231), MD4 (RFC 1320), MS-CHAPv2 / MPPE (RFC 2759/3079), окно повторов (`CryptoTest`).
- Полный IKEv2-туннель против скриптового ответчика `jvmtest/fake_ike.py` (22 сценария: алгоритмы, cookie, ошибки ключей, DPD, разрыв связи, подделки сертификатов и т.д.).

## ⚠️ Текущие ограничения

- **Кодеки**: поддерживаются PCMA (G.711 a-law) и PCMU (G.711 u-law). DTMF, TLS/SRTP и перевод звонка отсутствуют.
- **VPN**: только IPv4 (маршрутизация IPv6 направляется в blackhole для отката приложений на IPv4).
- **Входящие звонки**: не поддерживаются (приложение ориентировано на исходящие вызовы).
