## Правила аккуратных диффов и внесения правок (ОБЯЗАТЕЛЬНЫ)

### 1. Вёрстка и логика никогда не смешиваются
Баг правится отдельным минимальным диффом без переформатирования окружающего кода.

### 2. Стиль файла сохраняется
Стиль проекта строго зафиксирован в `.editorconfig` (4 пробела, без табов, без хвостовых пробелов, LF, скобка `{` на той же строке).

### 3. Минимальный дифф: трогаются только нужные строки
**СТРОГО ЗАПРЕЩЕНО без явной просьбы**:
- Переносить строки, менять порядок методов и импортов.
- Переименовывать или переписывать существующие комментарии (они на русском, русский остаётся).
- Добавлять или удалять пустые строки вокруг редактируемого блока.

### 4. Отступы выставляются по вложенности скобок
Перед правкой метода проверяется баланс `{` и `}` и уровень отступов.

### 5. Дифф строится от актуального файла
Дифф строится строго на основе текущей свежей версии файла в репозитории.

### 6. Формат правки зависит от размера
- **До ~5 строк:** блок «Файл / Метод / Найти / Заменить на». «Найти» — точная копия 2-3 строк из текущей версии, встречающаяся в файле ровно один раз.
- **Больше ~5 строк:** unified diff (`git diff`), контекст 3-5 строк, копируется точно, включая пробелы. Один хунк на один баг, в заголовке указан файл и метод.

### 7. Файлы целиком НЕ выдаются
При багфиксах выдаётся ТОЛЬКО дифф. Выдача файла целиком запрещена.

### 8. Код не удаляется молча
Любое удаление строки (включая `return`, `break`, скобки) отдельно объясняется: что делала строка и почему её убирают.

### 9. Порядок работы с пользователем
Нейросеть описывает баг, просит подтверждение, выдаёт один дифф. Следующий шаг — только после применения диффа пользователем и подтверждения результата.

### 10. Безопасное применение диффов
1. **Чистая точка отката:** Перед правкой `git status` чист. Откат: `git restore <файл>`.
2. **Сначала проверка:** `git apply --check --recount --ignore-whitespace patch.diff`.
3. **Применение:** `git apply --recount --ignore-whitespace patch.diff`.
4. **Хунк не правится руками:** Если не применился, запрашивается контекст вокруг места правки и создаётся новый дифф.
5. **После применения:** Сборка проекта (`:app:assembleDebug`) и проверка `git diff --stat`.
