# Промпт 2: Проектирование целевой архитектуры (KISS, SOLID, Clean)

## Требования к целевой архитектуре:
1. **Принцип инверсии зависимостей (DIP/SOLID):**
   - Наверх торчат ТОЛЬКО интерфейсы.
   - Реализации (`*Impl`, `Android*`) спрятаны на самых нижних уровнях/внутренних пакетах (`internal` / `impl`).
   - Верхние слои и модули работают исключительно через абстракции.
2. **Модульность:**
   - Если функциональность не вписывается в единый дизайн (например, VPN/IKEv2), выделить ее в отдельный модуль.
   - Каждый модуль имеет четкие границы API (интерфейсы наружу, реализация внутри).
3. **KISS & SOLID && DIP && DRY:**
   - Избегать избыточных зависимостей между модулями.
   - Минимизировать связность (coupling), максимизировать связность задач внутри модуля (cohesion).
